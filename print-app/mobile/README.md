# אפליקציית הדפסת מדבקות ותוויות גבינה

אפליקציית אנדרואיד (Expo + TypeScript) שמאחדת את `print.cohenb11print.com` ואת
`cheese.cohenb11print.com`. האפליקציה רק פונה לשרתים הקיימים. ההדפסה עצמה
ממשיכה לרוץ ב-BarTender על מחשב ההדפסה.

**לפני השימוש:** צריך להתקין את השינויים בשרתים (`../server/README.md`).
בלעדיהם השרתים לא מכירים את מפתחות הגישה, והאפליקציה לא תוכל להתחבר.

## מבנה

```
src/
  app/                 מסכים (Expo Router)
    _layout.tsx        RTL, ספקי הגדרות והיסטוריה
    settings.tsx       הגדרות + בדיקת חיבור
    (tabs)/index.tsx   מדבקות (מקביל ל-print.html)
    (tabs)/cheese.tsx  גבינות (מקביל ל-cheese-labels.html)
    (tabs)/history.tsx היסטוריה מקומית (50 אחרונות)
  api/                 שכבת ה-API עם טיפוסים, לפי הקוד של השרתים
    http.ts            מפתח גישה, טיימאאוט 30 שניות, הודעות שגיאה בעברית
    print.ts           GET /items, POST /webhook
    cheese.ts          /cheese-items, /cheese-preview(-upload), /cheese-label-image, /print-cheese-batch
  lib/settings.tsx     שם מזמין וכתובות (AsyncStorage), מפתח (SecureStore)
  lib/history.tsx      היסטוריה ו"הדפס שוב"
  components/ui.tsx    כפתורים ושדות גדולים
```

## פיתוח

```
npm install
npm run typecheck
npx expo start
```

לאפליקציה יש מודולים נייטיב (SecureStore, DocumentPicker), ולכן כדאי לבדוק אותה
בבניית APK ולא ב-Expo Go.

## בניית APK והתקנה על טלפון

1. ליצור חשבון חינמי ב-expo.dev, ואז, מתוך התיקייה הזו:
   ```
   npx eas-cli@latest login
   npx eas-cli@latest build -p android --profile preview
   ```
   בפעם הראשונה המערכת תשאל אם ליצור מפתח חתימה. לענות "כן".
2. בסוף הבנייה מתקבל קישור להורדת ה-APK. פותחים אותו בטלפון, מורידים,
   ומאשרים "התקנה ממקורות לא ידועים".
3. בפתיחה הראשונה: ממלאים שם מזמין ומפתח גישה, ולוחצים "בדיקת חיבור".

**חשוב:** את מפתח החתימה ש-EAS יוצר צריך לשמור. עדכון של האפליקציה בטלפון
דורש APK חתום באותו מפתח. EAS שומר אותו בחשבון באופן אוטומטי.

## עדכונים באוויר (בלי להתקין APK מחדש)
שינוי בקוד האפליקציה (מסכים, טקסטים, התנהגות) נשלח לכל הטלפונים בפקודה אחת, מתוך התיקייה הזו:
```
set EAS_NO_VCS=1
npx eas-cli@latest update --channel preview --message "תיאור קצר של השינוי"
```
הטלפונים מורידים את העדכון בפתיחה הבאה של האפליקציה, ומחילים אותו בפתיחה שאחריה.
כדי להחיל מיד: **הגדרות ← "בדוק עדכונים"**.

**מתי בכל זאת צריך APK חדש:** כשמוסיפים חבילה עם קוד נייטיב, או כשמשנים את `app.json`.
במקרה כזה מעלים את `version` ב-`app.json` (למשל ל-`1.1.0`), בונים APK חדש ומתקינים אותו.
עדכוני אוויר מגיעים רק לטלפונים עם אותה `version`.

**סוג מדבקה חדש לא דורש בכלל עדכון אפליקציה.** הוא מוגדר בשרת, ב-`label_types.json`
(ראה `../server/README.md`).

## בדיקות שבוצעו

- **שרתים** (בסביבת בדיקה, עם BarTender מדומה): בקשה בלי מפתח או עם מפתח שגוי
  נדחית. בקשה עם מפתח תקין עוברת. בקשה עם חתימת HMAC בלי מפתח (כמו JP Quality)
  מודפסת כרגיל. עבודה כפולה מחזירה `already_handled`. `skipDates` מרוקן את
  התאריכים. כל נתיבי הגבינות דורשים מפתח.
- **אפליקציה** (בגרסת דפדפן, מול אותם שרתי בדיקה): הגדרות ובדיקת חיבור (✓/✗),
  חיפוש, בחירה, הדפסת שקית, תיבת התאריכים מוסתרת בכשרות, תצוגה מקדימה של
  גבינות עם סימון כפולים, היסטוריה ו"הדפס שוב".

**לא נבדק, וצריך לבדוק בטלפון אמיתי:** תצוגת RTL מלאה, העלאת Excel, תמונת
התווית במסך מלא (בדפדפן היא לא נטענת, כי הדפדפן לא שולח את המפתח עם בקשת
תמונה), דיאלוג אישור ההדפסה, וכל ההדפסות מול BarTender האמיתי.
