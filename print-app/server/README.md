# שרתי ההדפסה – מפתחות גישה

התיקייה הזו מכילה עותק של הקבצים שרצים על מחשב ההדפסה (`C:\BarTenderWebhook`),
יחד עם השינויים שמוסיפים מפתח גישה (`X-Api-Key`) לשני השרתים.

## מה השתנה

| קובץ | שינוי |
|---|---|
| `api_keys.py` | **חדש.** קורא את המפתחות מ-`API_KEYS` שב-`.env` ובודק את הכותרת `X-Api-Key`. |
| `webhook_receiver.py` | `/items` דורש מפתח. `/webhook` מקבל **או** מפתח תקין **או** חתימת HMAC תקינה, כמו קודם. |
| `cheese_app.py` | כל הכתובות חוץ מהדף עצמו (`/`) דורשות מפתח. |
| `print.html` | הסוד הוסר מהדף. יש שדה "מפתח גישה" שנשמר בדפדפן. |
| `cheese-labels.html` | שדה "מפתח גישה". תמונת התווית נטענת עם המפתח. |

`/health` ו-`/status/<id>` לא השתנו.
`cheese_labels_routes.py`, `cheese_barcode.py`, `cheese_label_image.py` לא השתנו.

### JP Quality
JP Quality שולחת בקשות חתומות ב-HMAC, ולכן ממשיכה לעבוד בלי שום שינוי מצידה.
מפתח גישה נדרש רק מבקשה שאין לה חתימה תקינה.

## התקנה על מחשב ההדפסה

1. **גיבוי:** העתק את `C:\BarTenderWebhook` לתיקיית גיבוי.
2. **יצירת מפתחות:** מפתח אחד לכל עובד או טלפון. בחלון cmd:
   ```
   py -c "import secrets; print(secrets.token_urlsafe(24))"
   ```
   הרץ את הפקודה פעם אחת לכל מפתח.
3. **עדכון `.env`:** הוסף שורה (ראה `.env.example`):
   ```
   API_KEYS=yossi_phone:המפתח_הראשון,moshe_phone:המפתח_השני,office_pc:המפתח_השלישי
   ```
   השם שלפני הנקודתיים מופיע ביומן בלבד. מפתח קצר מ-16 תווים לא יתקבל.
   **אל תשנה את `PRINT_WEBHOOK_SECRET`.** JP Quality משתמשת בו (ראה "JP Quality" בהמשך).
4. **העתקת קבצים:** העתק לתיקייה את `api_keys.py`, `webhook_receiver.py`, `label_types.json`,
   `cheese_app.py`, `print.html` ו-`cheese-labels.html` מכאן.
5. **הפעלה מחדש** של שני השרתים.
6. **בדיקה:**
   - פתח את `print.cohenb11print.com`, הזן את המפתח בשדה "מפתח גישה", חפש פריט והדפס מדבקה אחת.
   - פתח את `cheese.cohenb11print.com`, הזן מפתח, וודא שרשימת המוצרים נטענת.
   - בלי מפתח: חיפוש פריט אמור להציג "מפתח הגישה חסר או שגוי".
   - **JP Quality:** שלח הדפסה אחת מהמערכת שלהם וודא שהיא יוצאת.

### ביטול טלפון אחד
מוחקים את הזוג `name:key` שלו מהשורה `API_KEYS` ומפעילים מחדש את שני השרתים.

### חזרה לאחור
אם משהו לא עובד: מחזירים את הקבצים מהגיבוי ומפעילים מחדש.

## הוספת סוג מדבקה חדש
סוגי המדבקות של דף ההדפסה ושל האפליקציה מוגדרים בקובץ **`label_types.json`**
(בתיקייה `C:\BarTenderWebhook`). דף ההדפסה והאפליקציה מקבלים את הרשימה מהשרת,
ולכן סוג חדש **לא דורש עדכון אפליקציה ולא הפעלה מחדש של השרת**.

1. מעצבים תבנית ב-BarTender, עם מקורות נתונים (Named Data Sources) בשמות של השדות שרוצים (למשל `product`, `sku`, `barcode`).
   אם רוצים תאריכים: `productionDate` ו-`expiryDate`.
2. פותחים את `label_types.json` בפנקס רשימות, מעתיקים בלוק קיים ומשנים אותו:
   ```json
   {
     "key": "jars",
     "name": "צנצנות",
     "templateKey": "standalone_jars",
     "labelType": "package",
     "template": "C:\\Labels\\JarLabel.btw",
     "headerTemplate": null,
     "fields": ["sku", "product", "barcode"],
     "dates": true
   }
   ```
   - `key`: מזהה באנגלית, בלי רווחים, שונה מכל השאר.
   - `name`: מה שכתוב על הכפתור.
   - `templateKey`: חייב להתחיל ב-`standalone_`.
   - `template` / `headerTemplate`: נתיב התבנית, עם **שני** לוכסנים הפוכים (`\\`). `null` = בלי תווית כותרת.
   - `fields`: אילו נתונים לשלוח. אפשר: `sku`, `product`, `barcode`, `kosher`, `passover`, `weight`, `packagesInfo`, `expiryDate`.
   - `dates`: `true` = השרת ממלא תאריך ייצור ותוקף, ומוצגת התיבה "הדפס ללא תאריכים".
   - `group` (לא חובה): כותרת שתחתיה יוצג הכפתור, למשל `"מדבקות לפסח"`. סוגים עם אותה כותרת מוצגים יחד.
   - `enabled` (לא חובה): `false` = הסוג מוגדר מראש אבל לא מוצג ולא מודפס, עד שהתבנית מוכנה.
     כשהתבנית מוכנה, משנים ל-`true` (או מוחקים את השורה).
3. שומרים. בין בלוקים צריך פסיק, ואחרי הבלוק האחרון אין פסיק.
4. בודקים: מרעננים את דף ההדפסה (או נכנסים מחדש ללשונית באפליקציה), והכפתור החדש מופיע.

אם הקובץ נשמר עם טעות, השרת ממשיך לעבוד עם הגרסה התקינה האחרונה, ורושם את השגיאה ב-`print_log.txt`.

## JP Quality – אין שום שינוי
- הנתיבים `/webhook` ו-`/status/<id>` מטפלים בבקשה חתומה בדיוק כמו קודם: אותה סיסמה, אותן כותרות, אותן תשובות.
- `PRINT_WEBHOOK_SECRET` נשאר כמו שהוא. אין צורך לעדכן את JP Quality בשום דבר.
- **סיכון שנשאר:** הסיסמה הזו הייתה גלויה בדף `print.html` הישן. מי שהעתיק אותה בעבר
  עדיין יכול לחתום על בקשות הדפסה. סגירת הפרצה הזו מחייבת החלפת סיסמה מול JP Quality,
  ולכן לא נעשתה כאן.

## Cloudflare Access (אופציונלי)
שכבה נוספת אפשרית. שים לב שהיא תחסום גם את JP Quality ואת האפליקציה, אלא אם
מגדירים להם Service Token או כלל Bypass לנתיב `/webhook`. לא הוגדר כאן.
